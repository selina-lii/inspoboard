Build a note taking app of your chosen framework; you can use a modern web based framework that's easy to work with, ultralight weight, and fast. the main view is a board like a microsoft whiteboard, has a tool bar similar to any pdf reader with icons: create note, create page, squibble, text, select (arrow), select (lasso), the structure is recursive meaning that when you open the note it is the same structure as the main view; you can keep going to any depth (althogh you shouldn't worry about the depths going too far); the main viewboard is an 'item' as is all other pieces of notes in the app, the items are visualized in a universe like a evidence board. items can be linked to each other so you can also think of it as a visualized hyperlink network (idk if any established app uses this framework). since there's a lot of note taking features you should try to use existing packages over reinventing the wheel. basically, a network of networks with two view modes, 2d and 3d. in the 3d view the item cloud can be rotated, you can drag one item relative to others, etc. item positions matter, they can be placed close/far from each other. maybe use a ultralight database to manage the data but the item contents should be plain text accessible. ofc you also need undo/redo stacks for all of these actions. each item has a name and can potentially just look like a txt/typora window if they're 'end nodes' but all notes can have text associated with them
  the app has basic functions of typora or msword, so it's mostly text-based. data integrity is the most important issue over any feature, ideally you wanna use a well established package of version control etc that note taking apps normally use to make sure data is never lost. app data is managed in a separate folder outside of the scope of this project; you should never access user app data but you will have test spaces with example texts; there're two versions of data, you only manage the data folder for testing. the app is entirely local. use dark, modern ui, similar to obsidian. let's think about what tools to build with first.
